## Выбор

Для проектирования выбрана связка: SQLite как СУБД и PlantUML с собственным скриптом `make_er.py` для ER-диаграммы.

Причины:

1. Агент работает без серверов, поэтому нужна встраиваемая база в одном файле. SQLite подходит, драйвер подключается обычной зависимостью.
2. Главное требование CASE-средства здесь: диаграмма должна соответствовать реальной базе. Скрипт `make_er.py` читает структуру базы (`PRAGMA table_info`, `PRAGMA foreign_key_list`) и строит диаграмму из неё, поэтому расхождения между схемой и рисунком невозможны.
3. Средства с графическим конструктором (MySQL Workbench, pgModeler) ориентированы на конкретные СУБД, не на SQLite. Онлайн-сервис dbdiagram.io требует браузера и ручного ввода. DBeaver и DataGrip строят диаграмму по готовой базе, но не автоматизируются из консоли.
4. Результат воспроизводим одной последовательностью команд из `README.md`.

## Ограничения выбора

Диаграмма текстовая, без интерактивного редактирования. Для изменения схемы правится `schema.sql`, после чего пересоздаются база и диаграмма. Если потребуется графический конструктор, схема из `schema.sql` загружается в DBeaver для просмотра, но этот вариант в работе не проверялся.
