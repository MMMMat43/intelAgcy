# Сравнение CASE-средств для проектирования и создания приложений

Задача: спроектировать и создать приложение «Журнал запусков генерации тестов» на языке Kotlin, которое использует базу данных из ЛР 11 (`agent_history.db`).

## Критерии

| Средство | Поддержка Kotlin | Генерация кода по модели | Обратная инженерия (код → модель) | Работа из консоли / CI | Лицензия | Порог входа | Запускалось в работе |
|---|---|---|---|---|---|---|---|
| PlantUML | Диаграммы любого языка как текст; разбора Kotlin нет | Нет | Нет (только через внешний генератор) | Да (`java -jar plantuml.jar`) | Бесплатно (GPL/MIT) | Низкий | **Да** |
| Свой генератор `kt2puml.py` (ЛР 10) | Да, разбирает исходники Kotlin | Нет | **Да**: классы, интерфейсы, связи, пометки шаблонов | Да (`.\run.ps1 uml`) | Наш код | Низкий | **Да** |
| IntelliJ IDEA (Diagrams, UML) | Да | Нет | Да, диаграмма классов по коду | Нет, только в IDE | Диаграммы в Ultimate (платно) | Средний | Нет, описано по документации |
| StarUML | Нет (Java через расширение) | Да, для Java и C++ через расширения | Частично, для Java | Ограниченно | Платно, есть пробный режим | Средний | Нет, описано по документации |

## Выбор

Выбраны **PlantUML** и **собственный генератор диаграмм классов `kt2puml.py`** из ЛР 10.

Причины:

1. Приложение пишется на Kotlin. Инструменты с генерацией кода по модели (StarUML, Visual Paradigm, Enterprise Architect, Modelio) генерируют Java, C# или C++, но не Kotlin, поэтому эта их возможность здесь не применима.
2. Диаграммы хранятся как текст рядом с кодом, попадают в систему контроля версий и пересобираются одной командой.
3. Обратная инженерия реализована своим генератором: диаграмма классов приложения строится по реальным исходникам, а не рисуется вручную. Пометки шаблонов проектирования берутся из конфигурации `patterns.json`, и скрипт `check_patterns.py` проверяет, что все упомянутые классы существуют в коде.
4. Всё бесплатно и работает без установки IDE.

Ограничение выбранного подхода: PlantUML не генерирует программный код по модели. Проектные диаграммы (варианты использования, последовательность, слои, макет окна) составлены вручную в PlantUML как проектные артефакты, а код написан по ним. Соответствие кода и проекта проверяется диаграммой классов, которую генератор строит по готовому коду.

## Что реально запускалось

- `java -jar plantuml.jar` (jar лежит в `labs-agent-materials/lab10-uml/tools/bin`) для отрисовки диаграмм в PNG и SVG.
- `kt2puml.py` через команду `.\run.ps1 uml`: построена диаграмма `07-history-app` по пакетам `com.example.agent.history` и `com.example.agent.history.ui`.
- `check_patterns.py`: проверка пометок шаблонов, результат `OK`.

Остальные средства в таблице описаны по их документации и в рамках работы не устанавливались.
