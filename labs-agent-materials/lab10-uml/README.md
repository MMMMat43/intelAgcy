# ЛР 10. Автоматическая генерация UML-диаграмм по коду агента

Диаграммы классов строятся по реальным исходникам `src/main/kotlin/com/example/agent`. Запуск одной командой из корня репозитория:

```powershell
.\run.ps1 uml
```

Команда выполняет три шага:

1. `tools/kt2puml.py` разбирает файлы `.kt`, строит модель классов и записывает `out/*.puml`;
2. шаблоны проектирования из `tools/patterns.json` накладываются на классы автоматически (стереотипы и цвета);
3. `tools/bin/plantuml.jar` рисует `out/*.png` и `out/*.svg`.

## Состав

| Файл | Назначение |
|---|---|
| `tools/kt2puml.py` | генератор: разбор Kotlin, связи, наложение шаблонов |
| `tools/diagrams.json` | какие классы и в какие диаграммы попадают, примечания |
| `tools/patterns.json` | соответствие «класс, шаблон», цвета шаблонов |
| `tools/check_patterns.py` | проверка: все классы из конфигурации есть в коде, в диаграммах нет посторонних слов |
| `tools/bin/plantuml.jar` | PlantUML 1.2025.2, рендер без Graphviz (режим `smetana`) |
| `out/` | результат: 7 диаграмм в `.puml`, `.png`, `.svg` и `summary.json` |

## Диаграммы

| Файл | Содержание | Шаблоны |
|---|---|---|
| `00-packages` | зависимости между пакетами (число импортов на связи) | |
| `01-source` | загрузка исходников | Strategy, Factory Method |
| `02-pipeline` | конвейер и подписчики | Facade, Observer |
| `03-storage` | хранение результатов | Repository, Bridge |
| `04-analysis` | разбор кода и модель данных | Singleton |
| `05-coverage` | подбор тестов по покрытию | Strategy |
| `06-execution` | выполнение и генерация тестов | Sealed result, Singleton |

## Проверка

```powershell
py labs-agent-materials\lab10-uml\tools\check_patterns.py
```

Проверка завершается с ошибкой, если класс из конфигурации исчез из кода или в `.puml` попало запрещённое слово.

## Что генератор умеет и не умеет

Умеет: классы, интерфейсы, `object`, `enum`, `data`/`sealed`, свойства из конструктора и тела, публичные методы, наследование и реализацию, ассоциации по полям (со множественностью для коллекций), зависимости по типам параметров и результатов, вложенные классы.

Не умеет: разбор полного синтаксиса Kotlin (используется разбор по тексту с учётом скобок, строк и комментариев), обобщённые ограничения типов, расширения, аннотации, видимость вложенных элементов сложнее `private`/`internal`/`protected`/`public`. Результат проверен на исходниках проекта и не претендует на универсальность.
