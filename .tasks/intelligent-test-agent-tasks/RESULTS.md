# Task 08: Результаты сквозной проверки (E2E)

## Что проверено

Проведена сквозная (end-to-end) проверка полного конвейера
`SourceLoader → JavaCodeAnalyzer → TestScenarioGenerator → JUnit5TestCodeGenerator → ArtifactStorage`
на двух заранее подготовленных Java-примерах с разнообразной логикой:

- `SampleCalculator` — методы `divide` (if/for/throw) и `isPositive` (if/else).
- `SampleStringUtils` — методы `normalize` (null-проверка, if, исключение) и
  `containsDigit` (for-цикл с условием).

Проверка реализована как автоматический тест
`src/test/kotlin/com/example/agent/e2e/PipelineE2ETest.kt`, который:

1. Загружает оба Java-файла через `LocalFileSourceLoader` (из временной директории `@TempDir`).
2. Анализирует их через `JavaCodeAnalyzer` и проверяет, что найдено ожидаемое количество функций.
3. Генерирует тестовые сценарии через `TestScenarioGenerator` **в fallback-режиме**
   (LLM-клиент детерминированно возвращает `Failure`, реального `LLM_API_KEY` не использовалось
   и сетевые вызовы не выполнялись) и проверяет, что для каждой функции есть минимум один
   `POSITIVE`-сценарий, а в целом по набору присутствуют `BOUNDARY`- и `NEGATIVE`-сценарии.
4. Генерирует Kotlin/JUnit5-код через `JUnit5TestCodeGenerator` и сохраняет все три вида
   артефактов (`analysis.json`, `test-cases.json`, `.kt`-файл в `generated-tests/`) через
   `ArtifactStorage`, проверяя их фактическое наличие на диске.

Сборка и полный тестовый набор проекта проверены командами:

```powershell
$env:JAVA_HOME = "C:/Program Files/JetBrains/PyCharm 2025.2.3/jbr"
.\gradlew.bat build --no-daemon
```

Результат: **BUILD SUCCESSFUL**. Проверка результатов выполнена не только по выводу Gradle
(который может показывать `UP-TO-DATE`), а по фактическим JUnit XML-отчётам в
`build/test-results/test/`.

## Известные ограничения

- Проверка велась без реального `LLM_API_KEY` — используется отдельный детерминированный
  `AlwaysFailingLlmClient` (аналог поведения `OpenAiCompatibleLlmClient` без ключа), поэтому
  вклад LLM-обогащения (`LlmScenarioEnricher`) в эту сквозную проверку не оценивался; все 24
  тест-кейса — результат чисто эвристической генерации (`HeuristicScenarioGenerator`).
- Компиляция сгенерированного `.kt`-файла с тестами отдельным Gradle source set/задачей не
  проверялась — по спецификации Task 06/08 достаточно того, что `KotlinPoet` успешно строит
  `FileSpec`, код синтаксически валиден (проверено в `JUnit5TestCodeGeneratorTest`, Task 06) и
  реально записывается на диск (проверено здесь через `ArtifactStorage`).
- Реальный live-прогон через n8n (импорт `integration/n8n/workflow.json` в работающий инстанс
  n8n и вызов REST API) не выполнялся — согласно `PLAN.md`, это вне проверяемых критериев;
  корректность REST-эндпоинтов, которые вызывает workflow, подтверждена отдельно тестами
  `RoutesTest` (Task 07, 3/3 теста пройдены: `/health`, `/analyze` успешный и `/analyze` с
  ошибкой 400).
- Метрика времени выполнения (~3086 мс) получена на одном локальном прогоне на конкретной
  машине разработки и приведена как иллюстративная, а не как строгий бенчмарк — для более
  точных цифр потребуется несколько повторных запусков с усреднением.
