# Проектные решения

Короткий список решений, их причин и цены. Подробности реализации в
`ARCHITECTURE.md`.

## 1. Только Kotlin

Первая версия анализировала Java (JavaParser), а тесты писала на Kotlin.
Перешли на Kotlin-вход по причинам:

- одна экосистема: код, тесты и инструмент на одном языке;
- разбор и выполнение опираются на один компонент: `kotlin-compiler-embeddable`
  строит дерево кода (PSI) и компилирует размеченную копию;
- тесты вызывают исходный код напрямую, без стыка между языками;
- меньше поддерживаемых конструкций, чем при двух языках.

Цена: обрабатываются только `.kt`, а Java-проекты не поддерживаются.

## 2. Алгоритм вместо чистой нейросети

Генерацию строит наш алгоритм (границы из условий, метки в ветках, отбор по
покрытию), а нейросеть вторична. Причины:

- **проверяемость.** Успех измеряется: ветка либо выполнена, либо нет.
  Предложение нейросети принимается только после реального запуска;
- **воспроизводимость.** При одинаковых входных данных и `seed` результат
  повторяется (с оговоркой про лимит по времени, см. `ARCHITECTURE.md`);
- **работа без сети и без ключа.** Все три примера проекта покрываются
  полностью без нейросети;
- **нет выдуманных значений.** Нейросеть может предложить вход, который не
  приведёт к нужной ветке. Здесь такой вход просто отбрасывается.

## 3. Golden master

Ожидаемые значения в `assertEquals` и `assertThrows` берутся из запуска кода.
Причины: автоматически знать правильный ответ без спецификации невозможно, а
запуск даёт настоящие, а не выдуманные значения, и сразу создаёт
исполняемые тесты без заглушек.

Цена, которую нельзя скрывать: тест фиксирует **текущее** поведение. Если в
функции есть ошибка, тест закрепит её. Пример из реального вывода:
`assertEquals(20.200000000000003, calculateDiscount(1.0, 101, true))`.
Такие тесты защищают от случайных изменений (регрессии), а не доказывают
правильность. Результат должен просматривать человек.

## 4. Гибрид с нейросетью на коротком поводке

Нейросеть привлекается только для веток, которые наш поиск не покрыл. Ей
отправляются сигнатура и условия этих веток; ответ разбирается строго
(JSON, все параметры, типы проверяются); каждое значение выполняется на
размеченной копии; принимается только то, что добавляет покрытие. Ожидаемые
значения в тестах всё равно берутся из запуска. Любая ошибка провайдера
(нет ключа, 403, 429, сеть, мусор в ответе) приводит к пропуску шага без
влияния на остальной результат.

Прежний вариант (свободный текст, значения-заглушки `llm-suggested`) был
удалён: такие сценарии нельзя выполнить, поэтому реальных проверок из них не
получалось, а вклад в результат был нулевым.

Статус: гибридный режим **вживую не проверялся**, потому что ключ провайдера
на момент проверок возвращал HTTP 403. Проверено тестами с подменой клиента.

## 5. Покрытие ветвей, а не условий

Метрика считает входы в ветви (`then`, `else`, тело цикла, элемент `when`,
`catch`). Это проще и надёжнее размечать текстовыми вставками. Цена: условия
внутри `&&` и `||` не проверяются по отдельности (не MC/DC), поэтому 100%
покрытия ветвей не означает проверки каждого подусловия.

## 6. Разметка текстовыми вставками

Метки вставляются правками текста по смещениям дерева, а не перестройкой
дерева. Так код компилируется штатным компилятором без дополнительных
проходов. Цена: ветки без фигурных скобок в неудобных местах помечаются как
не инструментируемые и попадают в `notInstrumentable`.

## 7. Компромиссы

| Решение | Цена |
|---|---|
| Встроенный компилятор Kotlin | Docker-образ 832 МБ, долгий первый запрос после старта |
| Выполнение пользовательского кода в процессе агента | Кандидат работает в отдельном потоке с таймаутом, но полной изоляции (песочницы) нет: код выполняется с правами агента. Не загружайте недоверенный код |
| Поддержка девяти простых типов параметров | Функции с объектами, списками, `enum` пропускаются |
| Лимиты поиска (150 попыток, 8 с на функцию) | Сложные условия могут остаться непокрытыми |
| Замер на трёх небольших файлах | Результаты нельзя переносить на реальные проекты |

Отдельно о безопасности: агент компилирует и выполняет загруженный код.
Запускайте его только на коде, которому доверяете, и не выставляйте порт 8080
в открытую сеть.

## 8. Что не сделано и что можно сделать дальше

- покрытие условий (MC/DC) вместо покрытия ветвей;
- параметры-объекты, коллекции и `enum` (построение значений через
  конструкторы и фабрики);
- функции с состоянием и внешними зависимостями (заглушки);
- мутационное тестирование для оценки силы тестов, а не только покрытия;
- реальная проверка гибридного режима с рабочим ключом и сравнение покрытия с
  нейросетью и без;
- песочница для выполнения кода;
- подключение `GitSourceLoader` к конвейеру (класс есть, но не используется);
- проверка на реальных проектах и сравнение с другими генераторами тестов.
