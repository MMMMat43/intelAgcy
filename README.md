# IntelligentTestAgent

Агент, который принимает исходный код на **Kotlin** и создаёт для него тесты
на **Kotlin/JUnit5**. Ожидаемые значения в тестах получены реальным запуском
кода, а не написаны вручную и не предложены нейросетью.

Собственный алгоритм проекта:

1. Разбирает код и считает цикломатическую сложность.
2. Достаёт из условий (`total >= 100.0`, `when`, проверки строк) значения,
   которые стоит проверить.
3. Размечает ветки кода, компилирует копию в памяти и запускает функции.
4. Оставляет только те входы, которые добавляют покрытие ветвей.
5. Записывает результат запуска как `assertEquals` или `assertThrows`.

Нейросеть необязательна. Она привлекается только для веток, которые алгоритм
не покрыл, и её значения принимаются лишь после проверки запуском.

## Быстрый старт

Нужны Windows, PowerShell и Docker Desktop.

```powershell
.\run.ps1 up
```

Команда собирает образ, запускает агента (`http://localhost:8080`) и n8n
(`http://localhost:5678`). Первая сборка занимает несколько минут.
Остановить: `.\run.ps1 down`.

Дальше откройте n8n, импортируйте `integration/n8n/workflow.json` и загрузите
`.kt`-файл через форму. Результат появится в `build\agent-output\<uuid>\`.
Пошаговая инструкция: [docs/USER_GUIDE.md](docs/USER_GUIDE.md).

Без Docker (нужен JDK 17 или 21):

```powershell
.\run.ps1 generate -Source путь\к\Файлу.kt
```

Полный список команд выводит `.\run.ps1`.

## Что получается на выходе

```
analysis.json                      структура кода, ветви, сложность
test-cases.json                    описание тест-кейсов для человека
coverage.json                      покрытие ветвей, непокрытые ветки
generated-tests/GeneratedTests.kt  готовые тесты JUnit5
```

Ответ API дополнительно содержит покрытие (`branchCoverage`,
`coveredBranches`, `totalBranches`), пропущенные функции и предупреждения.

## Измеренные результаты

Покрытие ветвей, одна и та же инструментация:

| Файл | Прежние эвристики | Алгоритм проекта |
|---|---|---|
| `OrderProcessor.kt` | 37/41 (90,2%) | 41/41 (100%), 68 тест-кейсов |
| `SampleCalculator.kt` | 6/7 | 7/7, 14 тест-кейсов |
| `SampleStringUtils.kt` | 6/7 | 7/7, 10 тест-кейсов |

Сгенерированные тесты для `OrderProcessor.kt`, скомпилированные вместе с
исходником, прошли 68 из 68. Тесты самого проекта: 93, без падений.

Как это читать: прежняя эвристика уже давала около 90% на `OrderProcessor.kt`,
реальный прирост около 10 процентных пунктов. Замер сделан на трёх небольших
файлах и не переносится на реальные проекты. Метрика считает ветви, а не
условия внутри `&&` и `||`.

## Ограничения

- Ожидаемые значения отражают **текущее** поведение кода. Ошибка в функции
  будет закреплена тестом как норма, поэтому результат нужно просматривать.
- Тестируются функции с параметрами `Int`, `Long`, `Short`, `Byte`, `Double`,
  `Float`, `Boolean`, `Char`, `String` и их nullable-вариантами. Остальные, а
  также `suspend`, generic, extension, `private` и подобные функции
  пропускаются и перечисляются в `skippedFunctions`.
- Недостижимый код и код, зависящий от состояния или ввода-вывода,
  остаются непокрытыми или дают нестабильные проверки.
- Агент выполняет загруженный код. Запускайте его только на доверенном коде и
  не открывайте порт 8080 наружу.
- Только Kotlin.
- Нейросеть в гибридном режиме вживую не проверялась (ключ провайдера
  отвечал 403), проверено тестами с подменой клиента.

## REST API

| Запрос | Назначение |
|---|---|
| `GET /health` | Проверка доступности |
| `POST /analyze` | Структура кода по пути `sourcePath` |
| `POST /generate-tests` | Генерация по пути `sourcePath` (путь виден серверу), `outputDir` необязателен |
| `POST /generate-tests-upload` | Генерация по загруженному файлу (`multipart/form-data`, часть `file`) |

Порт задаётся переменной `PORT` (по умолчанию 8080).

## Настройка нейросети

Скопируйте `.env.example` в `.env` и заполните `LLM_API_KEY`, `LLM_MODEL`,
`LLM_API_BASE_URL` (любой провайдер с API, совместимым с OpenAI). Файл
`.env` не попадает в git. Без него всё работает на собственном алгоритме.

## Структура проекта

```
src/main/kotlin/com/example/agent/
  source/       загрузка .kt
  analysis/     разбор Kotlin, ветки, сложность
  coverage/     границы из условий, метки веток, отбор по покрытию
  execution/    компиляция в памяти, запуск, приведение типов
  generation/   эвристики, предложения нейросети, постобработка
  codegen/      генерация тестов JUnit5 (KotlinPoet)
  llm/          клиент OpenAI-совместимого API
  api/          Ktor: маршруты, DTO, конвейер
  storage/      запись результата
integration/n8n/workflow.json   форма загрузки для n8n
docs/                           документация
run.ps1                         единая точка запуска
```
